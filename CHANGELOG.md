## [0.2.1] - 2026-09-17

### Added

- **Multi-item fs tools (`read_files` / `edit_files`)** — several operations in ONE call (cap 16 items), cutting tool-flight round trips and giving multi-edit workflows real atomicity. `read_files` takes `files: [{file_path, offset?, limit?}]` — one segment per item with `read_file`'s exact semantics behind a `=== path ===` header; a failed item reports its error inline and the rest still read (all items failing → one consolidated error). `edit_files` takes `edits: [{file_path, old_string, new_string, replace_all?}]` — same-file edits apply in listed order on the content the previous edit left (later edits may target text earlier edits introduced), and each FILE is atomic: one failed edit leaves that file untouched while other files still apply, so the report shows exactly which files were written and which edit (by its 1-based index in the model's own list) failed, with the nearest-line hint. Upfront validation rejects empty/identical/exactly-duplicated items and the cap before any I/O; CRLF handling generalizes `edit_file`'s gate (any `\r`-carrying old_string keeps that file in raw space). Under the hood: a new `#[derive(ToolItem)]` proc-macro generates object schemas for nested array-of-object parameters (the `Tool` derive delegates `Vec<Item>` items to `<Item>::item_schema()` for non-primitive item types — a missing derive fails compilation), and `read_file`/`edit_file` remain as the single-item path over the same extracted cores (`read_file_segment`, `apply_edit_ops`), their pinned schemas unchanged. The web tool-card summary renders multi-item args as "N items: <first path>".

- **The e2e harness runs axe-core accessibility scans** — a devDependency whose SOURCE the harness injects into the page (the runtime harness stays zero-dep): three surfaces per run (the fresh chat's empty state, the rendered conversation with prose + both verdict cards, the 390×844 mobile chat) must carry no critical/serious violations. The color-contrast rule is off by documented design (the faint token's tiered hierarchy — tokens.css) and `region` off (the shell is not landmark-partitioned). The first run caught three real defects, all fixed: the notification bell's unread badge was INSIDE the DropdownMenuTrigger's `asChild` span, so the trigger's button semantics landed on a span (aria-allowed-attr, critical) and AT lost the expanded state; the sidebar chat row was `role=button` with the ⋯ menu INSIDE it (nested interactive, serious) — the row and menu are now siblings under a positioning wrapper, same geometry, same keyboard path; prose links had no underline (Tailwind preflight strips it) and color alone is under the distinguishability threshold in the dark theme (link-in-text-block, serious) — `.prose a` underlines explicitly.
- **Coverage floors + a CI bundle treemap** — vitest coverage thresholds act as regression floors set just under the measured baseline (global 80/75/65 lines/functions/branches; `src/lib/**` 92/85/80; `src/core/**` 72/72/52 — the wire translation is exercised mostly through the e2e harness, not jsdom), so a silent coverage drop fails CI instead of passing quietly; verified the mechanism fails an impossible threshold. `FLUX_BUNDLE_ANALYZE=1` (the CI web job sets it) emits a rollup-plugin-visualizer treemap to `dist/stats.html`, uploaded as a CI artifact — build-time only, never shipped.

- **A skeleton primitive joins the loading voices** — `components/ui/skeleton.tsx`: static, token-derived shape placeholders (a fg wash reads on every surface) with the codebase's existing gentle opacity pulse — no shimmer sweep, the placeholder promises shape, not progress. Applied where a known shape is seconds away: the terminal host's first frame (undefined/connecting states paint three quiet bars instead of a blank inset void) and the Providers panel's first uncached catalog probe (the preview pane holds the "Upstream catalog" block's shape while the upstream round-trip runs — the badge alone carried it before). Deliberately NOT applied where loading is either instant or invisible: the "load earlier" pagination is a local slice over already-fetched messages, and the @-mention popup appears only once its listing resolves (a skeleton flash would add motion to a completion gesture).

- **File references in the composer (`@`-mention + drop-to-reference)** — typing `@` opens a path completion popup over the composer (`services/mention.ts`): workdir-RELATIVE completions with `/`-drill-down (choosing a directory keeps the `@` and continues into the next segment; choosing a file consumes it and trails a space), dirs first, capped, matched case-insensitively on the segment after the last `/`. Directory listings cache per session with a 15s TTL — the Explorer's refresh rhythm — so a file the agent JUST created is completable; the cache is independent of the Explorer's tree state (completion works with the Files tab never opened). The popup is composer-local: ArrowUp/Down rove, Enter/Tab insert, Escape closes locally (stopPropagation shields the app-level chain — closing a popup must not cancel a round), mousedown-before-blur keeps focus in the textarea. Dropping an Explorer row onto the composer inserts its path at the caret — rows are drag SOURCES (text/plain, the absolute path relativized against the chat's workdir; outside paths stay absolute and let the tool boundary reject them honestly); the tree still accepts no drops. IME-safe: an Enter during composition confirms the candidate, it does not insert.
- **Error rounds gain retry affordances; keyboard shortcuts get a sheet** — pane-context errors (`services/stream.ts`) render as a small danger card with two quiet token controls under the message: **Retry** walks back to the nearest user bubble and puts that turn's exact text back into the composer via the shared `flux:compose` bridge — it refills, NEVER auto-sends (the failed round stays in the transcript; stacking a second round on its context is the user's call, per the accepted T-08 split-manually tradeoff), and **Copy** carries the raw error text. The bare no-chat error (`services/dispatch.ts`) stays action-free — there is no turn to retry. The shortcuts sheet (`?` on the bare app surface, or the palette's "Keyboard shortcuts" action) reads its Application rows from the registry's own `shortcut` fields via `listShortcutRows()` — chords can never drift from the actions — plus the composer rows (Enter / Shift+Enter / Escape) that belong to no action; typing targets keep their literal `?`.
- **Command palette (Ctrl/Cmd+K)** — one input over a single action registry (`services/commands.ts`): every open conversation (switch = the shared `selectChat` path the sidebar rows use) plus the application verbs (new chat, transcript search, new terminal, toggle sidebar/dock, cycle theme, open settings — plain or directly at the Providers / MCP / Skills section, a one-shot intent the store carries), and reconnect (gated to an actual disconnection). Actions delegate to the owning services — the registry reimplements nothing; availability gates are evaluated per open. The palette is a Radix dialog with real listbox semantics (combobox input + `aria-activedescendant`, ↑/↓ wrap-around, Enter runs-and-closes, click runs, Escape dismisses through Radix before the app-level chain); its query is one-shot — reopening starts empty, unlike the find bar's remembered search. Two pieces of global state the palette exposed got promoted out of component-local state: the theme CHOICE now lives in the store (`services/theme.ts` owns what the choice does — the data-theme flip and the live terminals' palette re-read — so a store action never touches the DOM), and the settings dialog's open flag + section intent likewise; the TopBar consumes both from the store and behaves identically.
- **In-transcript search (Ctrl/Cmd+F)** — a scoped find over the ACTIVE chat's rendered pane (`services/transcript-search.ts` + `TranscriptSearchBar`): cross-node, case-insensitive, non-overlapping matches painted by the CSS Custom Highlight API (`::highlight(flux-search[-current])` in stream.css) — the append-only streaming DOM is never touched; engines without the API keep native find (the intercept is gated on the API + an active chat). Streaming appends rescan through a 150ms-debounced MutationObserver that re-counts but never re-scrolls (the view is not yanked by the round's output); Enter/Shift+Enter wrap around; Escape closes the bar BEFORE the round-cancel layer (one surface per Escape, same rule as the mobile drawer); the query survives close/open (find-bar memory); a chat switch closes the bar (search is per-conversation). Scope is the rendered transcript — older tail-paginated history joins the index when loaded. A batched switch+open commit cannot close what it opened: the bar's switch-close effect compares against the service's opened-for chat, not a mount-time ref.
- **The screenshot tour doubles as a visual regression net** — `npm run shots:update` snapshots the tour into a LOCAL, gitignored `e2e/.baseline/` (the session's accepted appearance — deliberately not a committed design contract: rendering is machine-coupled and the design stays free to move); `npm run shots:check` re-tours and pixel-diffs every shot against it, exiting 1 over a 0.2% budget with `<name>.diff.png` heatmaps in `.shots/`. Zero extra dependencies: the PNG decode and per-pixel diff run inside the already-launched Chrome (createImageBitmap + OffscreenCanvas, `e2e/visual-diff.mjs`); captures await `document.fonts.ready` and phase-lock infinite animations, so same-machine re-runs land 0 px on static shots.
- **The sidebar marks chats with a running round** — a global `running` flag joins the wire: `ChatInfo.running` (truth = the live task's round state; a task that died mid-round is done-filtered, so no ghost marker). The chats broadcast now also re-fires on ROUND boundaries, not just lease transitions: lifecycle's watcher subscribes the engine's round-state watch (flux-chat's state slot is a `tokio::sync::watch` — written only on real Idle↔Streaming transitions) and re-broadcasts per flip, plus one final broadcast when a task dies so a marker can never outlive its round. The sidebar row shows an accent spinner before the title for running chats — visible for background chats and rounds driven from OTHER windows (the flag is global truth, not viewer-scoped stream state), ORed with the local `streaming` flag so this window's own send lights it instantly; the row's accessible name grows ", running".

- **Provider editing (UpdateProvider)** — the Providers dialog's entries are no longer remove-only: an Edit affordance on the preview pane (desktop) and each row (mobile) opens a shared edit form that swaps the url / api key BEHIND the fixed id (the id is what chat pins and saved models reference — renaming stays remove + re-add). The api_key field is tri-state over the wire: absent keeps the stored key (it never leaves the server, so there is nothing to resend), present replaces it (empty clears). The url prefills with the effective one; validation is identical to add (unknown id, unknown protocol → inline errors). Pinned chats hot-apply the fresh endpoint: the registry persists first, broadcasts, then re-resolves every pinned chat's instance — the cache syncs and live engines re-begin on the fresh endpoint at their next machine gate (the switch path's carried-pin rebuild), with no `provider_switched` notice (the pin didn't move). New `refresh_chats_pinned_to` lifecycle primitive in flux-session; e2e pins the tri-state through the probe's Authorization header.

- **User messages carry a copy affordance** — an icon button sitting left of the bubble in the same slot the fork button owns (hover reveal on pointer devices, always visible + 36px tap floor on touch, `aria-label="Copy message"`). Clicking copies the bubble's exact text at click time (the multi-line `pre-wrap` content, not a re-rendered form) through the shared `copyText` path with its plain-HTTP fallback; success flips the icon to an accent check for 1.5s, failure stays silent (`copyText` already exhausted its fallback — a false "Copied" would be worse than none). Both affordances insert before the bubble body, so the order is canonical (copy · fork · bubble) on the history render AND the live-attach path (`attachForkToLiveBubble`). `lib/dom.ts` (`buildMsgCopyButton`), `styles/stream.css`.

### Changed

- **The two draggable panes now share a conversation floor** — the sidebar and the dock each clamped their widths against the viewport ALONE, so on a tablet-sized window (768–1024) they could jointly squeeze the conversation below usable (360 + 520 dragged an 800px viewport's column to −80px), and a dock width persisted from a wide monitor rendered unclamped on a narrow one. `core/prefs.ts` gains `CONVERSATION_MIN_WIDTH` (280px — the dock drag's existing promise, now actually enforced behind BOTH panes) with dock-aware `clampSidebarWidth` / sidebar-aware `clampPreviewWidth` used by both resizers, and `#right-dock`'s authored CSS width gains a render-time `min()` guard against `100vw − sidebar − floor` — the layer the drag clamp can't be, because it recomputes on every window change, not just on drags. The stored preferences are untouched; only what renders yields.
- **Tool cards speak the flight's outcome** — tool results ride the wire as plain strings, so every completion wore the same green "completed" voice, cancelled flights included. `dom.ts classifyToolResult` now reads the kernel's own string markers into a verdict: the `Error: ` prefix (a tool's Err or a crashed flight) takes the danger rail and keeps full opacity (settled cards fade; failures must not); the `[interrupted by user]` mark speaks "interrupted" in the warn voice (the user's own action — noticed, not alarmed); a trailing `(exit code: N)` speaks "exit N" in warn. That last marker is new on the kernel side: flux-tools' `format_command_output` appends the code for non-zero exits WITH output (the empty-output case already carried it), so a failing command's status is visible without cross-referencing stderr's presence — the model reads it too. Verdicts paint the summary voice only; result text is never rewritten (a successful command echoing "Error: …" is a documented, accepted false-positive face). The fake provider gains a second scripted call (`bash exit 3`) and ui-check pins the verdict end-to-end (`completed · 0.0s | exit 3 · 0.0s`).
- **Markdown prose details converged** — inline code trades its `--fx-inset` fill for a fg-based wash: inset sits at bg's luminance in the dark theme, so the chip's fill vanished there; a wash over the current surface lifts in dark / drops in light and reads on whatever it lands on (bg, elev, thinking blocks), no new token. Tables gain even-row zebra washes under the grid — vertical rules stay (a wide horizontally-scrolling table needs its columns) and the stripes add the row tracking the grid alone lacks. Blockquotes gain a recessed fill to partner their strong left rule (a bare rule read as indentation, not a quote); `hr` steps up to `border-strong` with a touch more air. The code-block language badge reads `muted` instead of `faint` (it sits ON the inset fill, where light-theme faint misses AA — and a language label is information, not garnish); the code copy button's hover lifts its fill to the elevation surface, the same hover language as the message copy button. The e2e fake provider's round-1 reply now carries every prose voice (inline code, fenced block, quote, hr, list) ahead of the pathological pair, so the conversation shots review them all.
- **Text-voice audit across the UI** — all 55 `text-faint` sites classified against the token contract: paths, timestamps, sizes, counters, percentages, placeholders, separators, icons and title-supplemented labels keep the faint voice; the sentences a user must READ — behavioral explanations in the settings panels (MCP apply semantics, skill git-source notes, model-section omission rules, the api-key storage assurance), the provider-switch dialog's apply timing, the terminal status bar's running/connecting lines — rise to `text-muted`. No token values moved: muted already clears AA on every surface in both themes (the math was re-derived for the audit); a `faint-strong` token was considered and rejected as redundant.

### Removed

- **The right dock's Round tab (round artifacts, F-11) — the whole surface, not a trim.** The tab was a derived index over the transcript: file rows duplicated what the stream's write/edit tool cards already show in order, MCP rows jumped to cards that live in that same stream, and shell (`bash`) rows — a working round runs many commands, each distinct string a truncated label — buried the 2–5 file rows that were the tab's actual payload. Its one unique action (opening a touched file in a preview) is the Explorer's every-day action, one click away on any file including those just written. Gone: the `Round · N` strip tab and `RoundPanel`, the `roundArtifacts` store slice, `services/artifacts.ts` (fold / dedupe / history-rebuild / reconnect-clear / jump-pulse) with its tests, and the `artifact-flash` CSS. The dock strip now holds only file tabs and terminal tabs — no dynamic tab churn mid-round; the transcript remains the round's record.

### Fixed

- **A mid-batch cancel followed by an engine rebuild no longer duplicates tool results in the provider request.** The machine's `pending` queue carries deferred tool-result voids / the in-flight tool's partial result across a user interrupt (that connection's prefix needs them on the next request) — but an in-place engine REBUILD re-begins its connection over the full persisted transcript, which already carries them, and the stale residue was then written into the request a SECOND time (duplicate tool messages: wasted tokens, broken prompt-prefix caching, strict OpenAI-compatible endpoints may 400). The gate fire (`GateReleased`) now DISCARDS `pending` — at that point every message in it is committed and present in the rebuilt prefix — while queued turns started BEFORE the gate still deliver the residue (they run on the pre-rebuild connection, whose prefix lacks it). Pinned by two machine tests: the fire-discard path and the pre-gate delivery path.
- **MCP supervisor: an entry-generation guard closes the remove→re-add respawn race.** An old supervisor waking from its backoff sleep identified its entry by id alone, so a remove+re-add of the same id during the window let it adopt the NEW entry: a duplicate session connected over the new supervisor's, the entry's `tool_names` got clobbered (the duplicate's registrations all collide and skip) and `cancel` re-pointed at the dead session — a later remove would cancel the wrong session and leak the live one's tools in the registry. Every connect (restore / add / respawn) now mints a monotonic generation paired with BOTH the entry and its supervisor; every entry-mutating step (quit handling, backoff wake, respawn adoption, `tools/list_changed` notices) re-checks the pair under the lock — a superseded supervisor drops its duplicate session (the dropped handle kills the child) instead of clobbering. The respawn adoption now also registers only after the entry check, so a vanished entry can no longer leak its registrations.
- **SSE tool-call fragments with an absurd `index` are dropped, not accumulated.** The tool-call accumulator sized itself straight from the wire's `index` field — a hostile or broken upstream naming `{"index": 1000000000}` in a few-byte JSON fragment allocated billions of entries (the 16 MiB stream cap bounds bytes, not this amplification). Indices at/above a cap (128 — legitimate streams are single digits) are dropped with a warn-once; real calls and the stream continue unaffected.
- Housekeeping: `flux-chat`'s flight supervisor dropped its write-only `interrupted` field; `flux-tools` fixed the one clippy lint (`is_some()` over a redundant pattern match); `buf.rs`'s module doc now matches the store's upsert semantics.

## [0.2.0] - 2026-09-16

> **Migration (script-installer users)**: the browser UI now ships INSIDE the binary —
> after upgrading, delete a previously unpacked `~/.flux/web-ui/` once (a stale dir
> becomes a per-path OVERRIDE that shadows the embedded UI; the startup log warns when
> it carries an old `web-ui-version.txt`). Source builds via `cargo` now need
> node/pnpm by default (a toolchain-less build embeds a placeholder page; headless-only:
> `--no-default-features`).

### Changed

- **The shipped binary drops from 32MB to 20MB** — `[profile.dist]` now builds with `lto = "fat"` + `codegen-units = 1` (cross-crate inlining/DCE, −4.5MB of `.text` at a release-only build-time cost) and `strip = "symbols"` (the ELF `.symtab`/`.strtab` were 8.2MB of dead weight with `debug = 0`). Accepted tradeoff: `RUST_BACKTRACE=1` in a shipped binary shows addresses without names — tool panics are caught and reported by payload (`flux-chat` tool_exec) and the shutdown contract is crash-only (T-11); dev `[profile.release]` stays unstripped for debugging. Attribution via cargo-bloat: `.text` 16.7MB led by rmcp 2.3MB, ~2.5MB of C/asm natives (sqlite3/aws-lc/zstd), std 1.6MB, the rustls/reqwest/h2/hyper stack ~1.6MB; embedded UI 2.5MB sits in `.rodata`.

### Added

- **The browser UI is EMBEDDED in the server binary** (rust-embed, feature `web-ui-embed`, default-on; decision T-14) — release builds serve `clients/web/dist` straight from the binary (+~2.5MB, the woff2 fonts dominate), debug builds keep reading the repo dist from disk at runtime (pinned to the compile-time path: the dev fallback — a UI rebuild needs no `cargo build`). Serving gains compile-time sha256 strong ETags (conditional requests 304) on top of the existing immutable/no-store split; MIME, HEAD/405 and the traversal guard (`..%2F` unit test) moved from `ServeDir` into the custom handler.
- **`crates/flux-server/build.rs` drives the embed** (Meilisearch-style): `rerun-if-changed` over web sources/dist/lockfile/proto (a vite rebuild's NEW hashed names are invisible to cargo's `include_bytes!` tracking — the build script rerun forces the macro to re-walk); invokes `scripts/package-web.{sh,ps1}` when the dist is missing/stale (node 24 + pnpm required); writes a placeholder index.html on toolchain-less checkouts so the binary still compiles (rust-embed validates the folder in ALL modes). Escapes: `FLUX_WEB_UI_NO_BUILD=1` skips the UI build; `--no-default-features` builds headless-only.
- **Per-path disk override with Gitea `custom/` semantics** — `--web-assets-dir` or `~/.flux/web-ui` (only when it exists) shadows the embedded bundle file-by-file; anything absent falls through to the embedded base. The four-level asset-resolution chain collapses to override-dir-or-embedded. A stale override dir still carries `web-ui-version.txt` and warns at startup (the stamp advisory now guards the only surface that CAN go stale — the embedded side cannot mismatch by construction).

### Removed

- **The standalone `flux-web-ui.tar.gz` release artifact (and the `web-ui/` payload in platform archives)** — the binary is self-contained; the script-installer flow is ONE command now, and the "② unpack the UI tarball into `~/.flux/web-ui`" README step is gone. `web-ui/` next to the binary is no longer a resolution level (re-populate `~/.flux/web-ui/` if you deliberately want a disk override). dist config: `include = ["web-ui/"]` and the `[[dist.extra-artifacts]]` block deleted; `.github/build-setup.yml` now supplies protoc + node/pnpm and lets build.rs build the UI inside the cargo build. flux-server is `publish = false` + `[package.metadata.dist] dist = true` (crates.io was never a distribution channel, and the embedded folder lives outside the crate dir).

### Fixed

- **The workdir VALUE now actually reaches the model** — `DEFAULT_PREAMBLE`'s comment promised per-chat workdir interpolation at the `begin` call site, but `compose_system_prompt` used the workdir solely to look up the skill catalog and never injected the path, so the model's only programmatic source for the path was `state_get("workdir")` — a round-trip the state schema's own enum advertised. Now `compose_system_prompt` states the boundary line (path + "sandbox boundary, fixed for this conversation") before the catalog at every begin (stable-before-volatile: the boundary never moves, the catalog refreshes at rebuild gates), and the state enum drops the `workdir` key (`INITIAL_STATE` keeps only `current_dir`) — the write refusal and the hidden read (`get("workdir")` serves the fixed field) stay.

## [0.1.5] - 2026-09-16

### Added

- **The Tier-1 skill catalog rides the system prompt** — every connection begin (the initial spawn AND an in-place engine rebuild) composes a begin-time catalog snapshot into the system prompt (`flux-chat/src/skills.rs`, new; the skill-format authority stays in flux-tools): the model sees what skills exist without spending a `skill_list` round-trip. `skill_list` remains the live rescan, `skill_read` the progressive-disclosure loader — the catalog is the passive overview, never a gate.
- **`skill_read` activation dedup is transcript-derived** — a `SkillActivationIndex` re-derives each chat's already-activated skill keys from the history at the two assembly points, hashed on the skill-format authority's normalization (frontmatter-stripped manifest body; raw bytes otherwise): re-reading an activated skill collapses to a dedup note instead of a second full injection, and fork / engine rebuild / restart inherit the dedup for free — no dedicated persistence, no directory watch (an accepted tradeoff, `docs/decisions` T-13).
- **The flux-server CLI is complete** — `--version`/`-V` follows the workspace release; every flag gains an `FLUX_*` environment fallback (`--host`→`FLUX_HOST`, `--port`→`FLUX_PORT`, `--db-path`→`FLUX_DB_PATH`, `--preamble`→`FLUX_PREAMBLE`, `--no-web`→`FLUX_NO_WEB`, `--web-assets-dir`→`FLUX_WEB_ASSETS_DIR`; precedence: CLI flag > env > default); `--generate-completions <bash|zsh|fish|powershell|elvish>` prints the completion script to stdout and exits before ANY logging or server setup (the stream stays clean for `>> ~/.bash_completion`); `--help` wraps to terminal width (`wrap_help`) and ends in copy-pasteable examples.
- **The saved-model list is session-level** — preloaded at session attach (`handlers.session_resumed`, re-pulled on every reconnect) so the ContextMeter and the cost estimate read it without any dialog ever being opened; the pickers and the Providers panel only READ the store (mutation broadcasts keep it fresh) — the panel is an editor, not the loader.

### Changed

- **The web UI component library is unified** — `components/ui` is ONE library: control primitives split into `button`/`fields`/`badge`/`spinner` behind an index barrel with the Radix wrappers as siblings (the monolithic `ui.tsx` deleted; imports unchanged); the Settings family extracted from `dialogs/` to `components/settings/` (SettingsDialog + the Providers/Mcp/Skills panels + ModelSection + the shared building blocks, ex `integration-ui.tsx`), and `dialogs/` keeps the promise-shaped family (`registry.tsx`, ex `impl.tsx`, + ConfirmDialog/NewChatDialog/QuestionCard); tests re-pointed.
- **`--fx-*` text tokens are WCAG-AA calibrated** — faint lifts from ~3:1 to 4.5+ on panel/elev (light `#6b7772`, dark `#7d8b87`) without merging into muted; light semantics + code voice clear 4.5 on inset; the audit is recorded in `tokens.css` comments. Alongside: empty-state rhythm (a larger brand wave, tuned spacing, the prompt rows borrowing the sidebar's 2px selection-rail vocabulary — inset shadow, no layout shift) and type/radius discipline (the topbar unread badge on the token scale, FileIcon radius on xs, the provider chip back to the control radius).
- **The models.dev catalog is served through an `Arc`** — cache hits clone the `Arc`, never the multi-MB catalog map (thousands of models) per hit.
- **Tests are hermetic by construction** — the proxy/`FLUX_*`-stripping ctor guard (a host `http_proxy` hijacked in-process reqwest clients into 502s — 17 phantom grpc failures — and `FLUX_*` vars leaked through the env into e2e server children) and the proxy-proof loopback test client moved into a dedicated DEV-DEPENDENCY-ONLY crate, `flux-test-support` (`test_env_guard!`; the var list lives once, and the crate docs forbid regular dependencies — the guard mutates process env). Wired into flux-server (main.rs + the separate `connect_e2e.rs` binary, replacing two copy-pasted ctor modules), flux-provider (lib tests + the separate `tests/models.rs` binary) and flux-mcp's Streamable HTTP test; `scripts/test.sh` still scopes `no_proxy` to loopback for the workspace run.

### Fixed

- **Switching between already-open conversations no longer flashes** — two compounding causes, both removed. (1) `chat_close` is a full exit (unsubscribe + release), so every switch back re-claimed, the server re-delivered the FULL history snapshot, and the client tore the pane down and rebuilt it unconditionally — 60× markdown+highlight on the main thread plus a whole-page `msgIn` replay, landing right after the pane had already faded in. `renderHistoryMessages` now keeps a per-pane fingerprint of the rendered snapshot (message count + last row id/content-length — the transcript is append-only) and skips the entire rebuild when the incoming snapshot is identical: DOM, scroll position, stick state and any "load earlier" pages survive untouched (a rebuild used to drop the loaded earlier pages on every switch). The DOM-presence gate keeps a wiped stale pane (whose cursor survives in the WeakMap) on the full-render path, and snapshots changed elsewhere while away (another window streamed) miss the fingerprint and re-render exactly as before. (2) `switchToChat` faded the target pane in from opacity 0 WHILE the outgoing pane faded out, dipping both to ~50% opacity at the transition midpoint — the background bleeding through read as the flash. A populated target now reveals instantly (the outgoing pane dissolves on top of it — a true crossfade); only a blank pane (first open / post-evict, still awaiting its snapshot) keeps the fade-in.

## [0.1.4] - 2026-09-16

### Added

- **The document title is a state surface** — the tab / PWA switcher / window list now reads `(2) Support — working… — Flux` instead of a static `Flux`: the active conversation's name, a `working…` mark while its round streams, and a `(n)` counter of background attention (rounds finishing or questions arriving in a NON-active chat while the tab is HIDDEN — a visible window already shows panes and toasts). Written on state transitions only (never per delta); the counter clears when the page becomes visible again (the browser-tab convention). Composition lives in `services/title.ts`, wired by one transition-gated subscription in mount.
- **Escape closes the mobile sidebar drawer** — the drawer is a fixed overlay without a Radix layer, so until now nothing dismissed it from the keyboard (the backdrop is mouse-only). It is the topmost surface while open: Escape closes it first and does not also cancel a streaming round underneath.

- **MCP over Streamable HTTP** — the MCP launch list gains a second transport: rows are now `stdio` (local child processes, unchanged) or `http` (a remote Streamable HTTP endpoint, the spec's other standard transport and the registry's dominant remote form). One row shape (`mcp_servers.kind`), one connect config (`McpServerConfig::Stdio | Http`), and the ENTIRE downstream machinery untouched — handshake, tool wrapping, `tools/list_changed` dual-path notices, the notice gate, the self-healing supervisor (a dropped HTTP session is the same `QuitReason::Closed` the backoff loop already respawns; the transport's own SSE-retry + session-recovery + re-init-on-404 ring absorbs transient blips inside), tool registration and engine rebuilds. HTTP rows carry `url` + `headers` — auth rides as an ordinary header (e.g. `Authorization`); header VALUES live in the database and never leave the server (secrets parity with env values / api_key), wire summaries carry `header_keys` only. Stateless servers accepted (`allow_stateless`); proxies come from the server process environment (`http_proxy`/`https_proxy`/`all_proxy`) with zero config — loopback targets are exempt (a `127.0.0.1`/`localhost` endpoint is a LOCAL server, the stdio tier's sibling; an ambient proxy that cannot reach the user's loopback would answer 502).
- **MCP panel transport picker** — the add form opens with a two-segment transport control (Command / URL in the app's segmented-tab language): stdio keeps the command/args/env fields, http shows url + headers (`KEY=VALUE` per line, the env parser's grammar). Rows and previews render the connect line per kind (launch line vs endpoint URL) with header-key badges.
- **Per-chat composer drafts** — switching conversations no longer loses the half-typed message. Each chat's pending composer text is saved when the composer unmounts (a switch away) and restored on return, keyed by chat id (`services/drafts.ts`; LRU-capped at 64, write-through to sessionStorage so a page reload restores too; writes only on save/clear, never per keystroke). Cleared on send; a fork's redo-turn prefill wins over the saved draft. Deletion paths (the authoritative chats broadcast, the sidebar confirm flow) prune drafts by id — deliberately NOT via `clearChatPane`, since pane LRU eviction ≠ chat deletion and the draft must survive an eviction.

### Changed

- **The streaming caret is gone** — the blinking `▍` at the live text tail is removed (CSS only). Streaming state stays visible through the typing indicator, the Stop button, and the composer's streaming border.

### Fixed

- **Composer sends during the disconnect window actually queue now** — the connection manager gated queueing on "an abort controller exists", but that object stays alive across the entire disconnect window (stream end → next backoff attempt, indefinitely on `failed`), so a message typed while the banner promised *"queued messages will be sent on reconnect"* instead fired a doomed RPC straight into the outage and surfaced as a spurious internal-error bubble. The gate now rides an explicit stream-attached flag (set by the `ready` handshake, cleared by connect/dispose/disconnect), an in-flight send that loses the stream mid-flight re-queues on a bare transport failure (definitive lease-gate statuses still map to their error frames), and the reconnect flush stops the moment the stream detaches (each failed send re-queues itself, so the drain loop cannot spin).
- **The assistant's question card is answerable again in multi-chat sessions** — the inline `question` tool card mounted into `.chat-pane:not([hidden])`, but panes hide with inline `display:none` (never the `hidden` attribute), so the query always hit the FIRST-created pane: with more than one visited conversation, the question (and its option buttons) materialized inside a background pane, invisible. Mounting is now by chat id (`question-card-<chatId>`), a question for a background chat pushes a discoverability toast, a pane wipe / chat deletion resolves the pending answer promise as dismissed through a new pending-question registry (services/dialogs) instead of hanging forever, and a newer question supersedes an older pending one.
- **Escape no longer cancels the streaming round while a Radix surface is open** — the window-level Escape handler fired alongside Radix's DismissableLayer (which does not stop propagation), so closing the Settings dialog or a row menu also killed the live round. The handler now ignores consumed events (`defaultPrevented`) and bails when an open `role="dialog"` / `role="menu"` / `role="listbox"` is mounted.
- **The mobile chat drawer is a drawer again, and always offers a way back** — two stacked defects made opening the conversation list a one-way door. The drawer's `#sidebar-layer` is a definite-width fixed box while the Sidebar root carries `flex-1`, so the grow silently filled the viewport: the authored `min(80vw, 300px)` width, the dimmed backdrop, and every "tap outside" affordance died under an opaque full-screen sheet, and the only way out was selecting a chat. `flex: none` lets the authored width govern again; the layer also starts below the top bar (`top: 3rem`), so the toggle — which now flips to an X while the drawer is open — stays visible and tappable as the close control (backdrop tap and Escape still close; the desktop pane is untouched).
- **Tapping a chat row's ⋯ no longer closes the mobile drawer (or selects the row)** — Radix opens the dropdown on pointerdown, but a tap still synthesizes a `click`, which bubbled into the row's `role="button"` activation: the leak selected the menu's own chat, and on the mobile drawer selection CLOSES the drawer — the list was yanked away mid-action with rename/delete unreachable. The row menu now contains its activators (click + Enter/Space stopped at the menu wrapper; Radix ignores click and owns those keys itself, so nothing else changes — on desktop the same leak would have handed the lease to the row behind the menu).
- **The mobile drawer no longer hides its covered content from keyboard and AT users** — the drawer is a fixed overlay on narrow viewports, but Tab focus walked straight through it into the main content it visually covers (and the dock's full-screen sheet behind it). While the drawer is open, the covered surfaces (`#main`, `#right-dock`) go `inert` via a `useCoveredByDrawer` hook (mobile regime only — the desktop sidebar is a side-by-side sibling, never an overlay); the TopBar stays outside so its toggle remains the way to close.
- **The sidebar resizer is keyboard-operable** — it carried `role="separator"` but no tabindex or arrow handling, unlike the dock's resizer (WCAG 2.1.1). Both separators now share one keyboard contract (`edgeResizeKeys` in the resize hook: ±24px per press, committed and persisted at once, direction named by the handle's side) and expose splitter ARIA (`tabindex`, `aria-valuenow/min/max`).
- **A cancelled resize gesture commits and detaches** — `pointercancel` (touch interrupted by a call, the browser claiming the pointer) left the drag listeners and the body drag-class attached, so the next pointermove dragged a dead gesture; the cancel path now commits the last moved width (the cancel event itself carries no meaningful coordinates) and fully detaches.
- **The Explorer's auto-refresh tick survives directory loads** — the interval effect keyed on the `refresh` callback (which changes with every `loaded`/workdir mutation), tearing down and re-arming on each load; a directory expanded within 15s of every previous load would never reach a tick. The tick is mount-once and reads the latest refresh through a ref.
- **Dock tab strip is a real ARIA tablist** — tabs carried `role="tab"` with no tablist, no panel association and a permanently-zero tabindex. The strip now owns `role="tablist"` with roving tabindex and Left/Right/Home/End activation; each tab names its panel (`aria-controls` / `aria-labelledby` on the single swapping tabpanel).
- **A `chatCreated` element without a chat payload is dropped and logged** — the translation used a non-null assertion (a malformed element would throw into the stream loop's catch as an opaque failure); it now throws a named error the loop reports precisely.
- **bash tool output is ANSI-stripped** — programs whose logging emits color unconditionally (e.g. `tracing` subscribers with the ansi feature; the runner's capture pipes already silence isatty-aware programs) no longer leak escape sequences like `[2m…[0m` into the tool result, the model context, and the UI card. `strip_ansi` lives in flux-tools and is applied ONLY in the bash tool by design — file tools (read_file/grep) stay byte-faithful so the model's edits round-trip against the real file content (T-12).

Two spec-dependent receive paths, verified against the official specs: spec ≤ 2025-06-18 pushes unsolicited (handler hook); spec 2026-07-28 notifies only subscriptions/listen streams — flux opens one for `toolsListChanged` and pumps it into the same sink (rmcp routes subscription notifications exclusively to the channel, so the paths never double-fire; a legacy server's rejection degrades to the hook). The `notifications/message` deprecation (SEP-2577, spec 2026-07-28) is handled with a scoped allow — it remains what deployed servers emit; progress notifications are deliberately NOT forwarded (request-scoped, token mapping would be guesswork).

## [0.1.2] - 2026-09-14

### Added

- **models.dev catalog status in the log** — the lazy catalog was completely silent: a fresh download logs at `info` with provider/model entry counts and elapsed time, every failure path (request, body read, HTTP status, parse) logs a `warn`, local cache hits log at `debug` with the cache age, and save-time enrichment logs its outcome. The default log filter is now `INFO` when `RUST_LOG` is unset — an empty `EnvFilter` passes errors only, which silenced startup and runtime logs alike.
- **Providers panel: filterable model catalog** — the probed upstream catalog (per provider) gains a live id-substring filter with a shown/total count, so import discovery works on catalogs that run to hundreds of ids.
- **models.dev matching ladder** — a catalog miss no longer silently drops enrichment. Matching is a three-stage best-effort ladder: literal forms (exact, `vendor/`-stripped, `:tag`-stripped), canonical equality (case + `.`/`-` spelling folded — vendors swap the two freely), and a canonical dash-bounded prefix fallback (dated snapshots like `-260828` or `-2024-08-06` extend a catalog base id; the longest catalog id wins). The zhipu/z.ai host family (`api.z.ai`, `open.bigmodel.cn`, `api.zhipu.ai`) anchors its GLM sections. An aliased match always reports the catalog's own id, and the saved-model row surfaces it inline (`matched: provider/model` + badge tooltip) — a wrong match is visible, never silent.

### Changed

- **Frontend package manager: npm → pnpm** — strict, symlinked resolution makes phantom-dependency imports structurally impossible; the pnpm version is pinned via `packageManager` and the scripts self-provision it when missing; the buf CLI rides `clients/web` devDependencies (no global installs); dependency build scripts are deny-by-default with an allowlist for the first-party toolchain (esbuild, @bufbuild/buf). Fixes the fresh-machine failure `buf: command not found` (the old skip-if-exists install could keep a stale install whose `.bin` lacked buf).
- **Node 24 LTS is the ONE supported frontend line** — `engines` declares `>=24 <25` (pnpm warns on anything else without breaking); CI and the release pipeline pin Node 24 explicitly; the scripts echo the resolved toolchain versions (`node`, `pnpm`) into the build log so environment drift is visible without digging.
- **The chat pickers' model datalist carries ONLY saved models** — the probed upstream catalog never bloats it; discovery/import lives in the Providers dialog, and free text still pins (the registry is a convenience, never a gate).

### Fixed

- **Model removal broadcasts the fresh list** — removing a saved model acked cleanly but never broadcast, so the deleted row stayed visible until the dialog was reopened; the removal now broadcasts the fresh list and rebuilds the matching chats (pinned params fall back to unset), symmetric with save.
- **pnpm 11's build-allowlist key** — `onlyBuiltDependencies` was renamed to `allowBuilds` in pnpm 11; a fresh install failed with `ERR_PNPM_IGNORED_BUILDS` before buf could resolve. The workspace yaml now uses the v11 key.
- **Script noise on newer Node** — pnpm 11's vendored `debug` probes storage backends and prints a localStorage `ExperimentalWarning` on every invocation on affected machines; the scripts suppress exactly that warning for their own node processes (guarded by a probe, so old Node that rejects the flag is unaffected).

## [0.1.1] - 2026-09-14

### Fixed

- **Shutdown is crash-only** — the graceful-shutdown machinery (`with_graceful_shutdown` + drain) is deleted: a Subscribe body never completes on its own (the keepalive pump runs forever), so waiting for connections wedged shutdown behind every open frontend. No signal handler is installed; durability is the storage layer's unconditional contract for every death mode: transcript commits are batch-atomic (a crash loses at most the live segment, and the persisted tail never carries a dangling tool_call), and tool children carry `PR_SET_PDEATHSIG` so a hard server death cannot orphan a running build.
- **`PR_SET_PDEATHSIG` is linux-only** — the `#[cfg(unix)]` gate broke macOS builds (`prctl` exists only in linux/android libc) and the unconditional re-export broke Windows; the helper is now a no-op on other platforms.

## [0.1.0] - 2026-09-14

### Added

- **Initial release** — a general-purpose coding agent framework: a Rust workspace (conversation kernel as a pure state machine + pump, OpenAI-compatible provider over SSE, supervised tool flights, MCP client bridge, SQLite persistence, session/lease layer) with a browser chat UI (React 19 + Radix + Tailwind v4) served on the same port as the Connect (gRPC-Web) API.
